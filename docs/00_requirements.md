# 공통 요청사항 정리 (항상 준수해야 할 원칙)

이 문서는 MES-System_v_0.5 개발 시 반드시 지켜야 할 공통 요구사항입니다. 신규 작업 전에 확인하고, 변경·추가 요청이 있으면 아래 항목을 갱신합니다.

## 필수로 지켜야 하는 요구사항
1. **한글, 자세한 설명**: 모든 질의·답변·주석·문서/UX 문구는 초보자도 이해할 수 있도록 한글로 자세히 작성합니다.
2. **진행 단계별 검증/테스트**: 각 기능/단계별로 자체 검증을 꼼꼼히 수행해 에러·경고 없는 상태를 유지합니다.
3. **주석 필수**: 개발 중 주석을 항상 남기고, 초보자도 이해할 수 있게 한글로 상세히 설명합니다.
4. **단일 exe 배포**: 최종 배포 시 단일 exe만으로 DB를 포함한 모든 시스템이 설치/구동되도록 설계·구현합니다.
5. **MES_Simulator 연동**: 기존 MES 연동 제조장비 시뮬레이터(MES_Simulator / Smart-Factory_Simulator)와 연동 가능하도록 개발하며, 향후 다른 장비 연동까지 고려합니다.
6. **Smart-Factory_Monitoring 연동 고려**: 다양한 장비의 통신 방식·데이터 형식을 고려하여 모듈화/확장성 있게 개발합니다.
7. **UI/UX 기준**: `docs/2025년 MES 웹서버 사용설명서.pdf` 내 화면 이미지를 기준으로 디자인합니다.
8. **무료·대중적 OSS 우선**: DBMS, Grid, Chart 등은 무료이면서 많이 쓰이고 설정이 간단하며 디자인이 깔끔한 오픈소스를 사용하고, 배포판에 자동 포함되도록 합니다.
9. **확장·유지보수 용이성**: 향후 기능 변경·개선·확대가 수시로 이뤄질 수 있으므로, 모듈화/계층화/설정 분리를 통해 손쉽게 수정·확장 가능한 구조로 개발합니다.
10. **운영 환경 호환성**: 로컬·클라우드 모두에서 운영 가능하도록 하고, Windows 계열과 Linux 계열(OS) 모두에서 실행·배포가 가능하도록 개발합니다.
11. **멀티 테넌트/기업별 DB 관리**: 여러 기업 담당자가 접속해 제조관리를 할 수 있도록, 기업별로 DB를 분리(회사 단위 스키마 또는 DB)하고 기업별 백업·복원이 가능하도록 구성합니다. 관리자(시스템·서비스) 화면에서 기업별 운영/계정/백업을 관리할 수 있도록 합니다.
12. **관리자용 기업 선택/구분**: 시스템·서비스 관리자는 모든 정보를 기업별로 구분해 조회·관리할 수 있어야 합니다. 모든 관리 기능에는 “기업 선택” 기능을 포함하고, 선택한 기업 컨텍스트로만 데이터를 조회/변경하도록 구성합니다.
13. **데이터/DB 암호화(매우 중요)**: 프로그램을 통해 수집·저장·변경·삭제되는 데이터는 외부 탈취/변조/삭제를 막기 위해 반드시 암호화(전송·저장 시)해야 하며, 관리되는 DB는 추가적인 암호화와 접근 통제를 적용합니다. 특히 개인정보 등 민감정보는 별도 강력 암호화 정책을 적용해 보호합니다.
14. **단순성·메모리 최소화**: 모든 소스코드는 가능한 복잡성을 배제하고 단순하게 작성하며, 시스템의 메모리 사용량을 최소화하도록 설계·구현합니다.
15. **원시 로그 보관/관리**: 외부 연계로 수집되는 원시 데이터(로그 데이터)는 일정 기간 안전하게 저장하고, 관리자가 해당 로그를 확인·조회할 수 있는 기능을 제공합니다.

## 운영 원칙
- 새로운 요구사항이 생기면 번호를 추가해 명확히 기록하고, 변경 일시/사유를 함께 남깁니다.
- 모든 변경 사항은 테스트 후 Git 기록에 남겨 추적 가능성을 확보합니다.
