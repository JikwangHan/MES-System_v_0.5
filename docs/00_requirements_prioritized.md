# MES-System v0.5 요구사항 및 우선순위 정리 (v0.3)
재사용성 및 단순성 중심 코딩 원칙 포함

- 문서 버전: v0.3
- 작성일: 2025-12-13 (KST)
- 적용 대상: MES-System_v0.5 (멀티테넌트, 암호화, 백업 및 원시 로그 보관 포함)
- 작성 목적: 요구사항을 우선순위로 정렬하고, 코딩 표준 및 운영 관점의 실패 포인트를 사전 차단
- 비고: v0.2 구조를 기준으로 보완. v0.2 원본이 필요할 경우 업로드 시 병합본 생성 가능

## 1. 문서 개요
본 문서는 MES-System v0.5 개발을 위한 요구사항을 우선순위로 정리하고, 개발 및 운영 단계에서 품질을 확보하기 위한 코딩 원칙을 함께 정의한다. 특히 멀티테넌트 운영, 데이터 암호화, 백업 및 복구, 원시 로그 보관, 단일 설치 배포(단일 exe 및 DB 포함)를 핵심 전제로 한다.

### 1.1 적용 범위
- 클라이언트 및 운영자 화면: 공통, 관리자, 생산, 품질, 장비, 시뮬레이터 연동 영역
- 서버 및 백엔드: 인증 및 인가, API, 비즈니스 로직, 배치 및 스케줄러, 데이터 계층
- 운영 및 보안: 테넌트 분리, 키 관리, 백업 및 복구, 감사 및 원시 로그, 모니터링 및 경보

### 1.2 우선순위 등급 정의
- P0: 런칭 필수. 미구현 시 서비스 제공 불가 또는 데이터 및 보안 리스크가 치명적임.
- P1: 안정화 핵심. 운영 품질 및 장애 대응에 직접 영향. 단기간 내 반영 권장.
- P2: 고도화. 생산성 및 분석력 개선. 단계적 확장에 반영.
- P3: 미래 준비. 표준화, 자동화 수준 향상 및 확장 옵션.

### 1.3 핵심 설계 원칙
- 단순성 우선: 복잡한 추상화보다 읽기 쉬운 직선형 데이터 흐름을 우선.
- 재사용성은 검증 기반: 반복이 확인된 공통 요소만 분리하며, 공통화 단위는 작게 유지.
- 경계 기반 구조: Presentation, Application, Domain, Infrastructure 역할을 명확히 분리.
- 운영 가능성 내장: 로그, 메트릭, 감사 및 원시 로그를 기능과 동일한 수준으로 설계.

## 2. 코딩 표준 및 품질 원칙 (v0.3 보완)
### 2.1 단순성 우선 규칙
- 한 함수는 한 가지 목적만 수행한다. 조건 분기와 예외가 늘어나면 즉시 분해한다.
- 입력 → 검증 → 처리 → 저장 → 응답의 파이프라인 유지.
- 과도한 패턴/추상화 금지, 외부 의존 분리가 필요할 때만 인터페이스 사용.
- 하드코딩 금지: 경로, 주소, 키, 임계치, 타임존은 설정으로 분리.

### 2.2 재사용성 설계 정책
- 3회 반복 시 공통화 후보로 승격, 공통화 단위는 작게.
- 업무 정책은 도메인에, 메커니즘(로깅/검증/재시도/변환/캐시)만 공통화.
- 거대한 유틸 클래스 금지, 작은 함수/컴포넌트 조합 우선.
- 테스트 가능성이 재사용성. 핵심 로직은 DB/외부 연동과 분리해 단위 테스트 가능하도록.

### 2.3 예외 처리 및 복원력
- 예외는 숨기지 않는다. 사용자 메시지/운영 로그/디버그 정보를 분리 기록.
- 재시도는 멱등성 설계와 함께. 멱등 키 없이 재시도 금물.
- 타임아웃 명시, 서킷 브레이커/폴백 준비.
- 부분 실패를 기본 시나리오로 간주.

### 2.4 성능 및 리소스 관리
- DB 접근: 페이징 기본, N+1 금지, 인덱스 기반 설계.
- 대용량: 전체 로딩 금지, 스트리밍/배치로 메모리 사용 제한.
- 커넥션/파일핸들/스레드 누수 방지 표준화.
- 성능 기준선 측정 후 변경 시 회귀 테스트.

### 2.5 보안 코딩 및 데이터 보호
- 입력 검증 표준화: SQL/Command/Path Injection 차단.
- 민감정보 로그 출력 금지, 마스킹/해시 적용.
- 키 관리/로테이션 고려, 키는 코드/설정에 저장 금지.
- DB 저장 데이터 암호화 일관 적용, 테넌트 분리/접근 통제 기본.

### 2.6 코드 리뷰 체크리스트
- 단순성: 책임 단일화, 분기 최소화, 하드코딩 제거
- 재사용성: 3회 반복 시 공통화, 공통화 단위 최소화
- 예외 처리: 표준 에러코드/로그, 멱등성
- 보안: 입력 검증, 민감정보 마스킹, 권한 체크
- 성능: 페이징, 인덱스, N+1 제거, 대용량 스트리밍
- 운영성: 원시 로그, 감사 추적, Correlation ID
- 테스트: 핵심 도메인 단위 테스트, 최소 1세트 통합 테스트

### 3.1 우선순위 적용 원칙
- P0는 설계/구현/테스트/운영 런북까지 한 세트로 완료.
- P1은 런칭 직후 안정화 스프린트에서 집중 반영.
- P2/P3는 데이터 품질 안정화 이후 단계적 고도화.

## 4. 기능 요구사항
### 4.1 공통 기능
- 로그인/로그아웃, 비밀번호 정책, 계정 잠금 정책
- 역할 기반 권한: 관리자, 기업 관리자, 일반 사용자 등 역할별 메뉴/API 접근 통제
- 공통 검색 및 필터: 기간, 상태, 태그, 기업(관리자 전용) 필터 기본 제공
- 공통 알림: 성공/실패/경고 표준 메시지 및 액션 가이드

### 4.2 관리자 서비스 (멀티테넌트 관리)
- 기업 등록/수정/비활성화, 계약 정보 관리
- 관리자 전용 기업 선택 필터: 모든 화면/리포트에서 기업 단위 조회/관리
- 기업별 사용자 및 권한 관리
- 기업별 백업/복구/보관 정책, 키 정책, 로그 정책 설정
- 감사 로그 및 원시 로그 조회, 내보내기

### 4.3 환경설정 및 통합 설정
- 장비 연동 통신 방식 선택/설정: TCP, UDP, Serial, OPC UA, MQTT 등 확장 가능
- 수집 데이터 종류/표출 방식 설정: 태그, 단위, 샘플링 주기, 보정값, 경보 기준
- 데이터 수집 방식: 폴링, 이벤트, 스트리밍
- 시스템 파라미터: 보관기간, 백업 주기, 성능 기준선, 운영 임계치

### 4.4 장비 관제 및 모니터링
- 실시간 데이터 수집/저장: 실패 시 재시도/누락 표시
- 실시간 대시보드: 장비 상태, 주요 지표, 알람 이력, 트렌드 차트
- 장비 제어 명령: 권한 기반 제어, 명령 이력 및 결과 수집
- 이력 조회/필터: 기간, 상태(Success/Failed), 태그별 필터

### 4.5 생산 관리
- 작업 지시, 생산 실적 수집, LOT 생성 및 추적
- 공정 단계별 이벤트 이력 저장/조회
- 재고 및 투입 자재 기록 연계 옵션
- 리포트: 기간별 생산량, 가동률, 작업 편차

### 4.6 품질 관리
- 검사 항목 정의, 검사 결과 수집/저장
- 불량 코드/원인 분류 관리
- 품질 추세 분석: 불량률, 공정별 결함 분포, 경보 기준 초과 알림
- 클레임 대응: LOT 기반 역추적 및 근거 데이터 제공

### 4.7 시뮬레이터 및 외부 연동
- MES_Simulator와의 이벤트/데이터 연동: 표준 메시지 포맷/버전 관리
- 연동 장애 대응: 원시 로그 저장, 재처리, 누락 이벤트 보정 절차
- 신규 장비 연동 시 어댑터 패턴을 활용해 핵심 로직 변경 최소화

## 5. 비기능 요구사항
### 5.1 보안 및 데이터 보호
- DB 저장 데이터 암호화: 민감정보 및 핵심 운영 데이터 컬럼 암호화
- 키 관리: 키 저장소 분리 및 로테이션 가능 구조, 키 접근 권한 최소화
- 전송 구간 보호: 내부/외부 연동 구간 TLS 적용
- 감사/추적: 사용자 행위 및 중요 이벤트 감사 로그 보관

### 5.2 멀티테넌트 분리 및 백업/복구
- 기업별 데이터 분리: DB/스키마/테이블 분리 전략 중 선택/적용
- 기업별 백업: 주기적 자동 백업 및 수동 백업 지원, 백업 보관 정책 설정
- 복구 리허설: 정기 복구 테스트로 RPO/RTO 달성 검증
- DR 옵션: Active-Standby, 복제 기반 전환 등 단계적 도입 가능

### 5.3 원시 로그 보관 및 운영 관측
- 외부 연동 원시 로그: 원문과 메타데이터 보관, 관리자 조회
- 보관기간 정책: 테넌트별 보관기간 설정/자동 파기
- 표준 로그 포맷: Correlation ID, 테넌트 ID, 사용자 ID, 작업명, 결과, 지연 포함
- 메트릭/경보: 요청 지연, 에러율, 큐 적재량, DB 연결 수 등 모니터링

### 5.4 성능 및 확장성
- 메모리 사용 최소화: 대용량 처리 시 스트리밍/페이징
- 응답 시간 목표: 화면/API별 목표 지연 정의/측정
- 동시 사용자 기준: 테넌트/동시 접속자 기준 정의 후 부하 테스트

### 5.5 배포 및 운영
- 단일 설치 배포: DB 포함 단일 설치 패키지 형태를 목표로 초기 구동 절차 자동화
- 업데이트/롤백: 버전 호환 마이그레이션 및 롤백 절차 문서화
- 운영 런북: 장애 대응, 백업/복구, 로그 조회, 키 로테이션 SOP 제공

## 8. 정리 및 적용 원칙
1. P1 요구사항은 설계·개발 전 과정에서 항상 준수해야 하는 “기본 법규”에 해당한다.  
   - 데이터 암호화, 키 관리, 통신 암호화  
   - 멀티테넌트 구조, 인증/인가 정책  
   - 코드/DB/SQL 단순성, 엄격한 검증, 운영 OS/배포 구조, 웹 취약점 대응
2. P2 요구사항은 1차 상용 버전까지 반드시 구현되어야 한다.  
   - 문서 기반 UI/UX, MES_Simulator 연동, 원시 로그/감사 로그, 오픈소스 선정 및 취약점 관리
3. P3 요구사항은 운영 단계에서 보안·안정성을 한 단계 더 끌어올리기 위한 고도화 항목이다.  
   - 백업 암호화, 키 회전, 보안·운영 문서 체계화

본 문서는 아키텍처 설계, DB 설계, API 설계, 화면 설계, 코드 구현, 테스트, 배포/운영까지 모든 단계에서 체크리스트로 활용한다.
