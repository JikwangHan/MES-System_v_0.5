# 데이터/DB 암호화 가이드 (요약)

본 문서는 MMS 시스템에서 적용할 데이터/DB 암호화 원칙과 권장 알고리즘을 정리한 것입니다. 모든 구현 시 이 가이드를 기준으로 적용/검증합니다.

## 1. 전송 구간 암호화
- HTTPS/TLS 1.2 이상 사용. 공인 CA 인증서 사용.
- 내부 서비스 간 통신도 가능하면 TLS 적용.

## 2. 저장(정적) 데이터 암호화
- 디스크/백업: DB TDE(Transparent Data Encryption) 또는 OS 레벨 디스크 암호화(LUKS/BitLocker 등) 적용.
- 컬럼 암호화(민감 컬럼): AES-256-GCM 권장(무결성 태그 포함). AES-256-CBC는 IV/패딩 관리 주의.
- 키 관리: 키는 코드에 하드코딩 금지. .env, KMS(Vault 등)로 보관하고 롤오버(주기적 교체) 정책 마련.

## 3. 비밀번호/토큰
- 비밀번호: bcrypt(코스트 10~12) 또는 Argon2id 사용. SHA256 단독 사용 금지.
- JWT: HS256/HS512(대칭) 또는 RS256/ES256(비대칭) 서명. 비밀키/개인키는 안전한 저장소(.env/KMS)에 보관.

## 4. 민감정보 필드별 권장
- 주민번호/금융정보 등 고위험: AES-256-GCM 컬럼 암호화 + 필요 시 마스킹 뷰 제공.
- 전화번호/이메일 등 개인정보: AES-256-GCM 컬럼 암호화, 조회 최소화, 검색 필요 시 토큰화/해시(블룸 필터 등) 검토.
- 로그/백업: 민감정보 로깅 금지. 백업 파일도 암호화(GPG/AES-256) 후 보관.

## 5. 무결성·접근통제
- GCM 인증 태그 검증 필수(복호화 전).
- RBAC: 민감정보 조회는 ROLE + companyId 범위로 제한.
- 키 접근 최소화 및 감사 로그 기록.

## 6. 적용 우선순위
1) 전송구간 TLS 1.2+ 필수 적용.
2) 민감 컬럼 AES-256-GCM 암호화 + 키 분리 저장.
3) 비밀번호 bcrypt/Argon2id 해싱.
4) JWT 키 안전 보관(KMS/.env), 롤오버 절차 마련.
5) 디스크/TDE 암호화 및 백업 암호화 적용.
